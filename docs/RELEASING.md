# Выпуск релиза и подпись exe

## Как это работает

| Событие                    | Что происходит                                                                    |
|----------------------------|-----------------------------------------------------------------------------------|
| `git push` / Pull Request  | `ci.yml`: тесты (Windows + Linux, Python 3.10 и 3.12), сборка exe, `--self-check`, артефакт |
| `git tag v1.0.0 && git push origin v1.0.0` | `release.yml`: тесты → сборка → self-check → (подпись) → GitHub Release с `ActivityTracker.exe` и `SHA256.txt` |

Скачать: вкладка **Releases** репозитория (или **Actions → запуск → Artifacts** для обычных коммитов).

`ActivityTracker.exe --self-check` запускается в CI на уже собранном файле: проверяет, что внутри лежат миграции,
иконки и GUI-библиотеки. Для сборок PyInstaller это самая частая причина «на CI зелёное, а exe не запускается».

## Почему Windows ругается и что с этим делать

Три разные вещи, их часто путают:

1. **SmartScreen («Windows защитила ваш компьютер»).** Срабатывает на файлы без репутации. Репутация считается
   **по файлу и издателю** и копится по числу скачиваний; у каждой новой версии неподписанного файла она начинается
   с нуля. С 2024 года EV-сертификат больше не даёт мгновенной репутации и ведёт себя как OV, так что платить за EV
   только ради SmartScreen не имеет смысла.
2. **Подпись.** Подписанный файл показывает имя издателя и позволяет накапливать репутацию на сертификат, а не на
   каждый файл. Неподписанный будет предупреждать каждый раз.
3. **Антивирусы (Defender и др.).** Приложение ставит **глобальные хуки клавиатуры и мыши**: эвристики похожи на
   кейлоггер, а одиночные exe от PyInstaller и так часто дают ложные срабатывания. Подпись снижает риск, но не
   отменяет его. Если сработало: соберите `--onedir` вместо одного файла, отправьте файл на анализ в Microsoft
   (ложное срабатывание) и в свой антивирус.

## Варианты подписи (проверено по документации Microsoft, 2026)

| Вариант | Цена | Подходит? |
|---|---|---|
| **SignPath Foundation** (бесплатно для open source) | 0 | **Лучший вариант**, если репозиторий публичный и под open-source лицензией. Издателем в Windows будет «SignPath Foundation», а не вы. Заявка рассматривается вручную. |
| **Microsoft Store** (MSIX) | $0 для индивидуальных разработчиков | Без предупреждений SmartScreen: приложение подписывает Microsoft. Требует упаковки в MSIX и прохождения проверки. |
| **Azure Artifact Signing** (бывший Trusted Signing) | ~$10/мес | **Недоступен из Узбекистана**: организациям только США, Канада, ЕС, Великобритания; частным лицам только США и Канада. |
| **OV-сертификат от CA** (DigiCert, Sectigo, SSL.com…) | ~$150–300/год | Работает везде, но ключ на токене/в облаке (с 2023), SmartScreen всё равно предупредит до накопления репутации. |

### Включить SignPath в этом репозитории

1. Репозиторий публичный, лицензия open source (добавьте `LICENSE`), релизы собираются в GitHub Actions.
2. Подайте заявку на signpath.org (бесплатный сертификат для open source).
3. В SignPath: проект со slug `activity-tracker`, политика подписи `release-signing`, подключённая система сборки
   GitHub.com, артефакт-конфигурация из `.signpath/artifact-configuration.xml`.
4. В GitHub → Settings → Secrets and variables → Actions:
   переменная `SIGNPATH_ORGANIZATION_ID`, секрет `SIGNPATH_API_TOKEN`.
5. Пуш тега: шаг «Подписать через SignPath» включится сам.

Названия входов action (`api-token`, `organization-id`, `project-slug`, `signing-policy-slug`, `github-artifact-id`, …)
я сверял по документации и примерам SignPath, но запустить подпись без вашей учётной записи не мог: при первом
запуске сверьтесь с github.com/SignPath/github-actions.

## Если подписи нет

Релиз соберётся и без неё (в логе будет «релиз будет НЕПОДПИСАННЫМ»). Windows покажет предупреждение:
«Подробнее» → «Выполнить в любом случае». В `SHA256.txt` лежит хеш для проверки скачанного файла.
